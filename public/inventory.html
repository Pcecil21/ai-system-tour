How I talk to Claude

There are three ways I reach Claude depending on what I'm doing: chat in a browser for questions and writing, a coding terminal for building software, and a desktop app for everyday automation.

Three entry points into the same underlying Claude system, each optimized for a different workflow.

Claude.aiWeb and mobile chat. Long-form reasoning, research, brainstorming. Accessible anywhere.
Claude Code CLITerminal-native agent. Builds full-stack apps, manages GitHub repos, runs tests. Powers the 45+ repo portfolio.
Cowork DesktopNon-developer automation hub. File management, MCP connectors, scheduled tasks, skill library. The daily cockpit.

What Claude knows before I say hi

Before I even type a message, Claude already knows my current priorities, recent work, project preferences, and which clients/projects I'm active on. I never have to start a conversation with "by the way, here's what I'm working on."

Before Claude responds, it assembles context from a layered hierarchy of instructions, skills, and memory.

How Hooks Load Context Automatically

Hooks are lifecycle scripts that fire at defined moments in a Claude Code session. The SessionStart hook runs before every session — a PowerShell script reads North-Star.md (current priorities), lists all vault files, and shows every file changed in the last 3 days. This means Claude has your priorities and recent work loaded before you type a single word. No manual copy-paste, no "here's what I'm working on" preamble — the system just knows.

It picks the right playbook

If I say "draft a trade rationale" or "build an onboarding checklist," Claude automatically grabs the matching playbook — think of it as a recipe card that tells Claude exactly how I like that kind of work done.

Skills are keyword-triggered instruction sets. When you say "trade rationale" or "onboarding checklist," the matching skill loads domain-specific best practices, templates, and workflows.

It uses live tools, not just text

Claude doesn't just talk — it actually does things. It can read my email, check my calendar, pull documents from Google Drive, design in Canva, open web pages, run code, and create Word/Excel/PDF files. Each of these is a "live connection" it can use on my behalf.

MCP servers connect Claude to external services. File tools, browser automation, and code execution handle everything else.

What is MCP?

MCP (Model Context Protocol) is a standard that lets Claude call external services through a unified interface. Each MCP server exposes "tools" — functions Claude can invoke. When you ask "what's on my calendar," Claude calls the Google Calendar MCP's list_events tool. The server handles auth, API calls, and returns structured data. This means Claude can read your email, check your calendar, search your files, and generate designs — all through the same protocol, without knowing the underlying APIs.

It remembers what matters

When I close a conversation with Claude, it doesn't all disappear. Important decisions, lessons, and client context get saved into notebooks (digital binders of notes). Next time I talk to Claude, it can look things up instead of asking me to re-explain.

Knowledge survives between sessions through Obsidian vaults, auto-memory capture, and structured decision logs.

How Obsidian Works

Obsidian is a local-first markdown knowledge base. Notes use [[wikilinks]] to create a connected knowledge graph. The Knowledge-Base vault holds 13 client household profiles with financial data, custodian exports, and CRM records — structured so Claude can instantly pull up any household's full picture. The second-brain vault holds project strategy, decision records, and a North Star priorities document that Claude reads at the start of every session via a SessionStart hook.

Some things run by themselves

I don't kick off every task manually. Every weekday morning a briefing lands in my inbox. Every Sunday night my projects get a health check. Every Friday evening a scan looks for waste. These run on a schedule, unattended.

Scheduled tasks run autonomously on cron schedules, handling routine operations without manual intervention.

Morning CockpitWeekdays at 7:00 AM. Scans calendar, email, tasks. Produces a daily briefing with priorities and flags.
Weekly Project HealthSundays at 7:00 PM. Audits all active projects for stale PRs, failing tests, dependency drift.
Token Waste ScannerFridays at 8:00 PM. Analyzes recent sessions for inefficient tool use, redundant reads, and cost optimization.

What are these words? (click to expand)

Playbook (a.k.a. Skill) — a saved set of instructions. When I say a trigger phrase, Claude loads the instructions and does the work my way.

Specialist (a.k.a. Agent) — a focused AI persona with a single area of expertise. Claude can hand off a subtask to a specialist when it needs deeper knowledge.

Live connection (a.k.a. MCP) — a plug-in that lets Claude actually reach out to Gmail, Calendar, Drive, custodian data, etc.

Notebook (a.k.a. Vault) — a folder of markdown notes Claude can read from and write to. Its long-term memory.

Trigger (a.k.a. Hook) — a little automation that fires on a specific event, like every time I start a new Claude session.
